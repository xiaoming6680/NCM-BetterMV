## 2026-10-17 性能优化与稳定性

对象：0.9.2 的渲染改动（后期缓冲去 MSAA、`textureLod`、粉尘取点、预热样本、换歌释放资源，见 [PERFORMANCE.md](PERFORMANCE.md)“已做的优化”）。

环境：i9-14900HX，RTX 5070 Ti 笔记本（驱动 32.0.15.8180，独显直连），32 GB 内存，屏幕 2560×1600 300 Hz、缩放 150%。网易云 3.1.37（Chrome 91）+ BetterNCM 1.3.x；无头 Edge 155（ANGLE D3D11）。歌：《Walk Thru Fire》（1332041346），seed 7。工具：`tools/bench/`。同一时段别的会话在跑视频渲染，GPU 被占去 20–40%，后半夜整机提交内存只剩 5–8 GB。

### 网易云里放歌（优化后，03:49–03:54，没跑完）

当前工作区构建装进 `plugins_dev`，`run.ts long --mode cpu`：列表循环，每分钟记一段。开测前整机提交内存空闲约 10 GB。

| 分钟 | 帧率（不限，300 Hz） | 每帧 CPU 中位 / p95 | 最长帧间隔 | GPU 进程显存 | 说明 |
|---|---|---|---|---|---|
| 1 | 112 | 2.5 / 4.3 ms | 37 ms | 1.38 GB | |
| 2 | 103 | 2.2 / 4.1 ms | 127 ms | 1.20 GB | |
| 3 | 95 | 1.8 / 4.4 ms | 主线程 1.4 s | 1.59 GB | 换歌：等待页 5.7 s（准备新歌），其间主线程有一次卡 1.4 s |
| 4 | 54 | 2.8 / 6.0 ms | 136 ms | 1.38 GB | 网易云各进程 CPU 同时降到一半，像整机在换页 |

第 5 分钟（03:54:22）网易云前端崩溃退出。崩溃记录里 JS 堆 82 MB / 98 MB，此时整机提交内存 60.6 / 62.3 GB（上限也从 68.7 缩到 62.3），几乎耗尽。同一晚另外几次崩溃（03:03–03:47）用的是别的会话的构建，其中 03:43、03:47 那两次是 OBS 会话分支的构建，不含这次的渲染改动，也一样崩，所以崩溃和整机内存耗尽有关，而不是这次的改动。页面报错只有网易云自己启动时的网络 404 和一次 fetch 失败，没有 MV 的报错。

- 只记 CPU 时帧率约 110，和带 GPU 查询时（约 100）差不多：上限不是测量造成的，在页面主线程上。
- 换歌时主线程卡 1.4 s 要查（准备新歌的某一段没分片）。

### 网易云里放歌，重测（04:28–04:41，通过）

别的会话的视频渲染结束、整机空闲提交内存约 17 GB（全程不低于 13.8 GB）时重测，构建为 main 0f37008 加本次改动。

| 项目 | 结果 |
|---|---|
| 长时间播放（列表循环 10 分钟，5 首歌） | 没有崩溃，没有 MV 的报错。帧率 190–290（不限，屏幕 300 Hz），每帧 CPU 中位 0.5–0.7 ms。GPU 进程显存 1.3–2.1 GB，随歌升降、不持续上涨；纹理、几何体在一首歌里随新歌词增加，换歌后回落（如 622 → 201） |
| 切歌（连切 6 首，每首 20 秒） | 每首都正常出画面，准备 2.5–8.8 s（显示等待页）。每帧 GPU 中位 0.6–1.3 ms、p95 1.7–2.8 ms（1813×1176） |
| 页面报错 | 只有网易云自己的请求失败：每次换歌一次 `orpheus://orpheus/pub/styles/undefined` 404、`skin.ls.css` 404、一张封面缓存 500、BetterNCM 插件市场域名解析失败。插件里没有 `<link>` 样式表，这些不是插件发的 |

- 第一次实测时帧率只有约 100、每帧 CPU 2–4 ms，是整机被别的渲染任务和内存压力拖慢；机器空下来后同一插件到 250–290 帧。
- 换歌准备时主线程仍会卡 0.5–1.3 s 一次（等待页的动画会停一下），是原有的准备流程，这次没改，记为待办。
- 测完还原网易云：音量 0.25、心动模式、暂停，重启核对过。
