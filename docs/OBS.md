# OBS 输出（issue #2）

直播时只把 MV 画面给 OBS，网易云的界面（搜歌、列表、设置）不进画面。参考 Folia 的“OBS 浏览器源”：OBS 里用同一套渲染器单独渲染，不放音频，固定地址，显示连接状态，OBS 显示画面时主窗口停渲染。

## 用法

设置 → 直播 → 打开“OBS 输出”，把地址 `http://127.0.0.1:32109/` 拖到 OBS 的预览区并确认（OBS 自动建一个浏览器来源，宽高等于画布，名为 BetterMV），或复制后在 OBS 中新建“浏览器”来源粘贴。声音照常由 OBS 采集桌面音频。

## 结构

```
网易云页面（插件）                     BetterMV OBS（本机服务，127.0.0.1:32109）          OBS 浏览器源（src/obs/page.ts）
src/plugin/obs.ts  ──POST /api/song/<文件>──▶ 内存里留 2 首  ◀──GET /song/<文件>──  解包 → MvPlayer.load（同风格、同种子）
                   ──POST /api/state──────▶ 广播 SSE        ──event: state──▶   按时间戳外推，渲染
                   ◀─GET /api/status（带密钥，2 s）─ 连接数、可见数  ◀──/events、/presence── 连上、在 OBS 里是否显示
                                            /、/obs.js、/fonts/ ← 插件文件夹的 obs\、fonts\
```

- **为什么要本机服务。** 插件运行在网易云的页面里，不能监听端口。BetterNCM 自己的本机服务端口每次启动都会变，写接口要 `BETTERNCM_API_KEY` 头。GitHub 上的同类插件要么导出文件给 OBS 的文本 / 图片来源（KINDYEAR-MusicInfo），要么把数据发给用户另外运行的服务（LyricsToPort、AMLL WS Connector）。Folia 是 Electron，主进程里直接起 Node 服务（`127.0.0.1:32108/obs`，`/obs/events` 用 SSE 推配置、时钟和实时音频，SSE 连接数就是“连接数”）。
- **考虑过的其他做法。**
  - 本地文件加拖放：OBS 浏览器源选“本地文件”，页面用 `<script>` 轮询插件写的状态文件。原型做过，同步也准，但插件不知道 OBS 是否连着，用户嫌设置麻烦。
  - 原生 DLL：BetterNCM 会把 manifest 里 `native_plugin` 的 DLL 加载进网易云的主进程、渲染进程和 GPU 进程（InfLink-rs 的日志可证），可以在主进程里起服务。但要装 Rust 工具链，代码跑在网易云进程里，出错会带崩网易云，每改一次都要重启网易云。
  - OBS WebSocket 一键添加：要用户先在 OBS 里开启 WebSocket 服务、复制密码，反而更麻烦。
- **本机服务（`src/obs/helper/BetterMVObs.cs`）。** C# 5，用每台 Windows 10/11 都有的 .NET Framework 4.x 编译器编成 12 KB 的无窗口程序（`scripts/build-obs.ps1`）。HttpListener 只监听 `127.0.0.1` 和 `localhost`，不需要管理员权限。网易云退出（连续两次检查不到 `cloudmusic` 进程）后自己退出。
- **启动和管理（`src/plugin/obs.ts`）。** 先问 `/api/status`：同版本的服务在运行就直接用（网易云在它退出前重新打开）；别的版本先让它退出再换；端口被其他程序占用就报错，设置里可改端口。程序从插件文件夹复制到 `<数据目录>\BetterMV\obs\bettermv-obs.exe` 再运行，因为 BetterNCM 每次启动都会重新解压插件文件夹，而程序运行时文件被占用。启动用 `cmd /c start "" /b`，和歌词对齐包启动 `pythonw` 的方式相同。服务消失后自动重启。
- **安全。** 密钥存在插件设置里，用 `x-bmv-key` 头传。写接口要密钥；`/api/status` 不带密钥只回应用名、版本和端口，带密钥才有连接数和服务里的歌曲（歌曲文件名就是在播的歌曲 ID）。`/api/` 对 http / https 来源（浏览器里的网页）一律 403，不回 CORS；只对 `orpheus://`（网易云页面）、`null` 这类非网页来源回显 CORS。`/events`、`/presence`、`/log`、`/song/` 只接受同源（OBS 页自己）或不带 Origin 的请求，免得别的网页冒充可见的 OBS 页让 MV 页停渲染。静态文件只从插件文件夹的 `obs\`、`fonts\` 里取，路径比较带分隔符。
- **歌曲数据（`src/obs/snapshot.ts`）。** `"BMV1"`、头长度（u32）、JSON 头（`PreparedSong`，类型化数组、`THREE.Color`、风格、非有限数字换成标记）、对齐到 8 字节，再接各类型化数组的字节（各自 8 字节对齐）。封面纹理换成 JPEG data URL 放在头里，调色板和封面像素原样传。一首 3 分钟的歌约 17 MB，九成是立体声。插件端只是拼 Blob，页面端直接在 ArrayBuffer 上建视图，不复制。文件名是 `<歌曲 id>-e`，对齐包对好歌词后换成 `-w` 重新发。
- **状态。** 正在播的歌（名称、歌手、封面地址，供等待画面）、歌曲文件名（服务里有了才填）、计划（风格、关掉的场景和画风、这首歌的歌词延迟、种子）、网易云的播放秒数和当时的 `Date.now()`、是否在播、画面延迟。插件在状态变化、时间跳变超过 0.3 秒（跳转）时立即发，播放中每秒补发一次。驱动它的是网易云的 PlayProgress 事件而不是定时器：窗口最小化后定时器会被压到一分钟一次。
- **种子。** 以前每次在 MV 页加载歌曲时由播放器自己抽种子；现在由插件按“这一次播放”抽（`playSeed`），MV 页和 OBS 页用同一个，所以两边是同一个 MV。“换一种”抽新的，OBS 页随之重排。“固定编排”仍按歌曲 id。
- **MV 页关着也跟歌。** 打开 OBS 输出后，切歌时即使 MV 页没开也准备新歌（和打开 MV 页时一样，分片分析），准备好就发给服务；不创建网易云里的渲染器。关闭 MV 页不再取消正在准备的歌。
- **OBS 显示时 MV 页停渲染。** 服务按页面上报统计“可见”的 OBS 页：OBS 的 `obsSourceVisibleChanged` 事件，以及 OBS 隐藏来源时页面的 `visibilitychange`（OBS 把不显示的来源切到后台）。有可见页面时，网易云的 MV 页不画新帧，等待画面显示“画面正在 OBS 中显示”；设置“MV 页同时显示”可关掉这一行为。
- **OBS 页（`src/obs/page.ts`、`plugin/obs/index.html`）。** EventSource 收状态（断线 1 秒自动重连，网易云重开后不用刷新 OBS），fetch 取歌曲。对时：`t + (Date.now() − at)` 减画面延迟，误差超过 0.25 秒直接跳，小误差按每帧 5% 吸收；没有新状态时最多外推 5 秒。没在播的歌、正在准备时显示和 MV 页一样的等待画面（封面模糊旋转、封面、歌名）。在 OBS 里（有 `window.obsstudio`）不显示提示文字。出错发到服务的 `/log`，状态里留最近 12 条；地址加 `?debug` 时连每一步加载都记。

## 实测（2026-10-17）

本机：开发页代替插件（`bmv.obsSend()`，按音频播放发状态），headless Edge 打开 `http://127.0.0.1:32109/`。

| 项目 | 结果 |
|------|------|
| 服务启动 | 约 1.8 秒 |
| 上传一首歌（17.2 MB） | 105 ms |
| OBS 页第一首 | 1988 ms（读 104，解包 6，建场景 617，预热 1047） |
| 画面时间对音频的误差 | 中位数：播放 −3 ms，恢复播放 −4 ms，跳转后 −2 ms，切歌后 −1 ms；5%–95% 在 ±13 ms 内 |
| 暂停 | 画面不动 |
| 切歌 | 新歌发出后 1449 ms 出画面 |
| 关掉 OBS 页 | 606 ms 后连接数归零 |
| SSE 推送延迟 | 1–3 ms |

真 OBS（32.1.2，CEF 127；用独立的便携配置，WebSocket 自动建来源、截图）：

| 项目 | 结果 |
|------|------|
| 建浏览器源后服务认出 OBS 页 | 1.2 秒（`obs: 1`） |
| 第一首出画面 | 4.8 秒（读 44 ms，解包 10，建场景 1582，预热 2763） |
| 暂停时 OBS 画面与 MV 页同一时刻 | SSIM 0.99995 |
| 在 OBS 里关掉 / 打开这个来源 | 可见数 0 / 1 |
| 删除来源 | 2.4 秒后连接数归零 |

网易云 3.1.37 + BetterNCM 1.3.4（开发构建装进 plugins_dev，带 `--remote-debugging-port=9222`，用 CDP 控制；OBS 页先用 headless Edge，再用真 OBS）：

| 项目 | 结果 |
|------|------|
| 设置“直播”分区 | BetterNCM 插件管理页（左侧分区栏）和 MV 页面板“全部设置”两处都在，深色宿主正常；打开开关 1.3 秒后服务就绪，状态“等待 OBS 连接”，OBS 连上后变为“OBS 已连接” |
| MV 页关着时跟歌 | 切歌后 1.7–3.8 秒歌曲送到服务（缓存里没有的歌走在线获取，也正常） |
| OBS 页（Edge）对网易云时钟的误差 | 中位数：播放 −2 ms，恢复 −3 ms，跳转后 7 ms（p95 22 ms）；暂停时不动 |
| OBS 显示时的 MV 页 | 每秒 0 帧，显示“画面正在 OBS 中显示”；OBS 页关掉后立刻恢复 |
| 真 OBS | 4–6 秒出画面；切到下一首 2 秒内跟上 |
| 网易云退出 / 重开 | 退出后 2.7–4.5 秒服务结束；重开后 2.7–5.6 秒服务自动启动，OBS 页自动重连（连接 1，可见 1），不用刷新 |
| 关掉“OBS 输出” | 服务退出，插件状态回到“未开启”；默认关闭时不启动服务，PlayProgress 上的钩子第一行就返回 |

实测中有一次网易云重开后服务 30 秒没起来，原因没查清（同一段时间网易云前端还崩过一次，整机可用提交内存长期只有 5–11 GB）。之后加了一次重试：第一次没起来，2 秒后再复制、启动一次（旧服务正在退出时，程序文件和端口可能还占着）。当晚网易云在 MV 运行时前端崩溃过几次，与是否开着 OBS 输出无关（报告在 `%LOCALAPPDATA%\NetEase\CloudMusic\webdata\file\crash_report`，JS 堆都只用了几十 MB）。

## 已知限制

- OBS 先于网易云打开时，浏览器源加载失败，要在来源上右键“刷新”。之后网易云重开会自动重连。
- OBS 里第一首歌要 4–5 秒出画面（建场景和着色器预热），这期间显示等待画面；之后的歌约 1.5 秒。
