# OBS 输出

直播时只把 MV 画面交给 OBS，网易云的界面不进画面。OBS 的浏览器源用同一套渲染器单独渲染，不放音频；地址固定；设置里显示连接状态；OBS 显示画面时网易云里的 MV 页停止渲染。

接入方式：设置“直播”中打开“OBS 输出”，把 `http://127.0.0.1:32109/` 拖到 OBS 预览区（OBS 自动建一个与画布同尺寸、名为 BetterMV 的浏览器源），或复制地址新建“浏览器”来源。声音由 OBS 的桌面音频采集。

## 结构

```
网易云页面（插件）                     BetterMV OBS（本机服务，127.0.0.1:32109）          OBS 浏览器源（src/obs/page.ts）
src/plugin/obs.ts  ──POST /api/song/<文件>──▶ 内存里留 2 首  ◀──GET /song/<文件>──  解包 → MvPlayer.load（同风格、同种子）
                   ──POST /api/state──────▶ 广播 SSE        ──event: state──▶   按时间戳外推，渲染
                   ◀─GET /api/status（带密钥，2 s）─ 连接数、可见数  ◀──/events、/presence── 连上、在 OBS 里是否显示
                                            /、/obs.js、/fonts/ ← 插件文件夹的 obs\、fonts\
```

### 为什么要本机服务

插件运行在网易云页面里，不能监听端口；BetterNCM 自己的本机服务端口每次启动都变，写接口还要 `BETTERNCM_API_KEY`。其他方案：

- 本地文件 + 轮询：OBS 浏览器源选本地网页，页面轮询插件写的状态文件。原型能同步，但插件不知道 OBS 是否连着，接入步骤也多。
- 原生 DLL：BetterNCM 会把 manifest 里 `native_plugin` 的 DLL 加载进网易云各进程，可以在主进程里起服务。但要 Rust 工具链，出错会带崩网易云，每次修改都要重启网易云。
- OBS WebSocket 一键添加：要先在 OBS 里开启 WebSocket 并填写密码，步骤更多。

### 本机服务（`src/obs/helper/BetterMVObs.cs`）

- C# 5，用 Windows 10/11 自带的 .NET Framework 4.x 编译器编成约 12 KB 的无窗口程序（`scripts/build-obs.ps1`）。HttpListener 只监听 `127.0.0.1` 和 `localhost`，不需要管理员权限。
- 连续两次检查不到 `cloudmusic` 进程后自行退出。

### 启动与管理（`src/plugin/obs.ts`）

- 先请求 `/api/status`：同版本的服务在运行就直接用（网易云在它退出前重新打开）；版本不同先让它退出再换；端口被别的程序占用则报错，端口可在设置中改。
- 程序从插件文件夹复制到 `<数据目录>\BetterMV\obs\bettermv-obs.exe` 再运行：BetterNCM 每次启动都重新解压插件文件夹，而运行中的程序文件被占用。
- 启动用 `cmd /c start "" /b`（与对齐包启动 `pythonw` 相同）。服务消失后自动重启；首次启动失败时 2 s 后重新复制并启动一次（旧服务退出时程序文件和端口可能还被占用）。
- 设置里的地址能拖进 OBS（`src/plugin/obsSettings.ts`）：地址是一个 `draggable` 的 `div`，`dragstart` 里把 `地址?layer-name=BetterMV` 同时写进 `text/uri-list` 和 `text/plain`，OBS 据此建一个同画布尺寸、名为 BetterMV 的浏览器源。它不能是 `<a>`：网易云自己的样式给链接设了 `-webkit-user-drag: none`，盖过 `draggable` 带来的 `element`，在 `<a>` 上 `dragstart` 根本不触发（地址“拖不动”的原因）；元素上另写了 `-webkit-user-drag: element`，不依赖页面的样式。用自己编的一个小窗口接住真实的鼠标拖放验证过：收到 `UnicodeText`、`UniformResourceLocator(W)`、`text/x-moz-url`、`FileGroupDescriptorW`，内容是该地址，和从浏览器里拖一个链接出去一样；没有拖进真的 OBS（会改动用户的场景集合）。
- “OBS 输出”默认关闭，关闭时不启动服务，PlayProgress 钩子第一行就返回。

### 安全

- 密钥存在插件设置里，用 `x-bmv-key` 头传递。写接口要密钥。`/api/status` 不带密钥只返回应用名、版本和端口，带密钥才返回连接数和服务里的歌曲（文件名即歌曲 ID）。
- `/api/` 对 http / https 来源（浏览器里的网页）一律 403、不回 CORS；只对 `orpheus://`（网易云页面）和 `null` 这类非网页来源回显 CORS。
- `/events`、`/presence`、`/log`、`/song/` 只接受同源（OBS 页自己）或不带 Origin 的请求，防止别的网页冒充“可见的 OBS 页”让 MV 页停渲染。
- 静态文件只从插件文件夹的 `obs\`、`fonts\` 取，路径比较带分隔符。

### 歌曲数据（`src/obs/snapshot.ts`）

- 格式：`"BMV1"`、头长度（u32）、JSON 头（`PreparedSong`：类型化数组、`THREE.Color`、风格，非有限数字换成标记）、对齐到 8 字节，然后是各类型化数组的字节（各自 8 字节对齐）。封面纹理换成 JPEG data URL 放在头里，调色板和封面像素原样传。
- 3 分钟的歌约 17 MB，九成是立体声 PCM。插件端只拼 Blob；页面端直接在 ArrayBuffer 上建视图，不复制。
- 文件名 `<歌曲 id>-e`；对齐包给出逐字时间后换成 `-w` 重新发送。
- 序列化时不带封面纹理（否则 `JSON.stringify` 会先调用纹理的 `toJSON`，把整张图编码成 PNG），封面 JPEG 每首只编一次，放在单独的任务里。

### 状态

- 内容：正在播的歌（名称、歌手、封面地址，供等待画面）、歌曲文件名（服务里已有时才填）、计划（风格、关掉的场景和画风、这首歌的歌词延迟、种子）、网易云播放秒数及当时的 `Date.now()`、是否在播、画面延迟。
- 状态变化或时间跳变超过 0.3 s（跳转）时立即发送，播放中每秒补发。驱动来自 PlayProgress 事件而非定时器：窗口最小化后定时器会被压到一分钟一次。

### 种子

种子按“这一次播放”由插件抽取（`playSeed`），MV 页和 OBS 页共用，两边是同一支 MV。“换一种”抽新种子，OBS 页随之重排。“固定编排”仍按歌曲 id。

### MV 页关着也准备歌曲

打开 OBS 输出后，切歌时即使 MV 页没打开也会准备新歌（同样分片），准备好就发给服务，但不在网易云里创建渲染器。关闭 MV 页不取消正在进行的准备。

### OBS 显示时 MV 页停渲染

服务统计“可见”的 OBS 页：OBS 的 `obsSourceVisibleChanged` 事件，以及 OBS 隐藏来源时页面的 `visibilitychange`（OBS 把不显示的来源切到后台）。有可见页面时，网易云里的 MV 页不画新帧，等待画面显示“画面正在 OBS 中显示”。设置“MV 页同时显示”可关闭这一行为。

### OBS 页（`src/obs/page.ts`、`plugin/obs/index.html`）

- EventSource 收状态（断线 1 s 后重连，网易云重开后无需刷新 OBS），fetch 取歌曲。
- 对时：目标时间 `t + (Date.now() − at)` 减画面延迟；误差超过 0.25 s 直接跳，小误差每帧吸收 5%；没有新状态时最多外推 5 s。
- 无歌或准备中时显示与 MV 页相同的等待画面（模糊旋转的封面、封面、歌名）。在 OBS 里（有 `window.obsstudio`）不显示提示文字。
- 错误发到服务的 `/log`，状态里保留最近 12 条；地址加 `?debug` 时记录每一步加载。

## 实测

开发页代替插件（`bmv.obsSend()`，按音频播放发送状态），headless Edge 打开 OBS 页：

| 项目 | 结果 |
|------|------|
| 服务启动 | 约 1.8 s |
| 上传一首歌（17.2 MB） | 105 ms |
| OBS 页第一首 | 1988 ms（读 104、解包 6、建场景 617、预热 1047） |
| 画面时间对音频的误差 | 中位：播放 −3 ms，恢复 −4 ms，跳转后 −2 ms，切歌后 −1 ms；5%–95% 在 ±13 ms 内 |
| 切歌 | 新歌发出后 1449 ms 出画面 |
| 关掉 OBS 页 | 606 ms 后连接数归零 |
| SSE 推送延迟 | 1–3 ms |

OBS 32.1.2（CEF 127，独立便携配置，WebSocket 自动建来源）：

| 项目 | 结果 |
|------|------|
| 建来源后服务认出 OBS 页 | 1.2 s |
| 第一首出画面 | 4.8 s（读 44、解包 10、建场景 1582、预热 2763 ms） |
| 暂停时 OBS 画面与 MV 页同一时刻 | SSIM 0.99995 |
| 隐藏 / 显示来源 | 可见数 0 / 1 |
| 删除来源 | 2.4 s 后连接数归零 |

网易云 3.1.37 + BetterNCM 1.3.4（开发构建，CDP 控制）：

| 项目 | 结果 |
|------|------|
| 设置“直播”分区 | 插件管理页和 MV 页“全部设置”两处都有，深色宿主正常；打开开关 1.3 s 后服务就绪 |
| MV 页关着时跟歌 | 切歌后 1.7–3.8 s 歌曲送到服务（在线获取的歌同样正常） |

## 已知限制

- **OBS 先于网易云打开**：浏览器源加载时服务还没起来（连接被拒），OBS 不会自动重试，需在来源上右键“刷新”。页面加载成功之后，网易云重开由 EventSource 自动重连。设置“直播”页和 README 写明了这一点。备选方案（未做）：
  - OBS 里改用本地网页文件（数据目录里的小页面，始终能打开，探测到服务后跳转）：任何顺序都行，但接入方式变成文件，拖文件进 OBS 未验证。
  - 服务开机自启、网易云退出后不结束：地址始终可用，但多一个常驻进程和自启项，卸载可能残留，未签名程序自启易被误报。
  - OBS WebSocket 联动（服务起来时刷新来源，还能一键添加）：需要先开启 WebSocket 并填密码。
  - 服务运行到注销：只剩开机后首次先开 OBS 的情况需要刷新。
- OBS 里第一首歌要 4–5 s 出画面（建场景和着色器预热），期间显示等待画面；之后约 1.5 s。
- 有一次网易云重开后服务 30 s 没起来，原因未查清（当时整机可提交内存只剩 5–11 GB）；之后加了上面的一次重试。
