# 歌曲分析

插件在歌一开始时分析整首歌，得到节拍、重拍、速度曲线、段落和能量曲线，导演据此排分镜。代码在 `src/analysis/`，入口 `analyzeSteps()` / `analyze()`。

## 约束

- 跑在网易云 3.1.37 的内嵌 Chromium 91 里：不用 Chrome 91 之后才有的接口（`Array.prototype.at`、`findLast`、`Object.hasOwn`、`structuredClone`、静态类块等）。
- 客户端的安全策略禁止 blob Worker，分析只能在主线程分片跑：`analyzeSteps` 是生成器，每 `sliceMs`（默认 8 ms）交还一次控制权。
- 纯 TypeScript，无依赖（FFT 自己写），结果确定。
- 输入：`OfflineAudioContext` 解码到 22050 Hz 后混成单声道的 `Float32Array`；16 kHz 以上的其他采样率也可以。
- 可选输入：歌词（帮助找段落）、`bpmHint`（网易云音乐百科的 BPM，只用来选倍频或 3∶2 的那一档）。

## 方法

1. 频谱：约 46 ms 窗、100 fps 的 STFT → 对数梅尔带 → 全频段与低频的起音强度、各频段包络。
2. 速度：起音强度的局部自相关给出速度候选，Viterbi 连成随时间变化的速度曲线（能跟住渐快）。每个时间窗按"节奏证据 × 响度"定可信度，安静或无节奏的地方沿用邻近速度。
   - 附点脉冲：鼓打贝斯的底鼓相隔一拍半，路径会停在真实速度的 2/3 上。路径速度的 ¾ 和 3⁄2 在速度图里都比它本身更强时，改用其中更强的那个（《Combine》116 → 87，百科 86）。
3. 节拍：动态规划跟踪，再做"恒速锁定"——一长段的节拍大多落在同一个恒定网格上时，整段换成该精确网格（能把只有反拍镲片的段落拉回正拍），最后平滑去抖。
   - 锁定的网格会向两侧延伸，跨过 DP 跑偏的地方（切分的旋律贝斯、附点延迟让局部速度证据不可靠的 drop），只要网格仍落在起音上；相位一致、中间隔着整数拍的两段网格会连起来。
   - 半速的歌里，拍子可能选在拍手上、底鼓落在半拍：只有当半拍处的底鼓明显更强、起音也不弱、低音变化不少于拍位时，才把整首移半拍（《Maybe》）。
   - 平滑只动 DP 的拍，锁定的网格原样保留；奇异时不解方程。最后保证节拍严格递增、落在歌里。
4. 小节相位与拍号：强拍证据来自低音与和弦变化、音色与响度变化、底鼓、歌词行起点；军鼓标出 2、4 拍。3/4 只在明显更像时才判。6/8 按两小节一组的 4 拍处理。
5. 段落：按小节的自相似矩阵找边界（特征里有 150 Hz 以下和 4 kHz 以上的电平），加上响度/密度跳变、**低音进出**（电子和流行歌最常见的换段信号）、歌词线索、响段前的空拍和**尾声起点**，动态规划选边界；再按重复句块把各遍副歌切得一致，重选一次。
   - 歌词线索：开始唱、句子重复度变化、重复句块的起点（句块里至少两句不同的词，相邻两句之间空着不超过 4 小节——隔着一段 drop 的两句不算一块；出现三次以上的句块多半是副歌，信号更强）、第一次唱到一句 12 小节以后还会再唱的词且前两句都只唱一次（主歌交给副歌或预副歌）、**主唱停下**。主唱不含人声切片：前后都是同一句、或短句且离别的词一小节以上的重复句；整句在括号里的词算和声。带冒号的行：冒号前紧贴着 8 字以内的说话人标记（男：、女：、合：、Rap:）时去掉标记照常算；其余带冒号的行当歌词解析没认出的制作名单丢掉，1.5 s 内紧跟的一行也丢。
   - 主唱停下 4 小节以上而音乐照样响：副歌交给 drop，常常只有这一个变化，单凭它就能切段（3 分）；停下的第一小节若是 drop 前的空拍，切在空拍之后。
   - 尾声起点：后半首里第一个"此后再也没有前 4 小节那么响"的小节（处处低 2 dB、平均低 3 dB）——只撤掉鼓或低音的尾声，比起全曲的 drop 和 break 是很小的变化（《Maybe》159 s）。渐弱跨两小节时两小节都给，由乐句长度决定。
   - 重复句块：某个边界正好由一句开头、而这句连同下一句在 12 小节以外还出现一两次时，其他各遍的同一位置得到该边界新颖度 0.6 倍的线索（最多 2），重选边界。第二遍副歌常常比第一遍变化小（主歌已经撤了低音），靠第一遍带出来（《Hurricane》113.5 s、《Stronger》161.8 s）。同一句在全曲反复出现（整段副歌都是它）则不传。
   - 长度：8/16 小节免费，其他长度只略加代价（一小节的弱起让 7、9 小节很常见）；超过 26 s 每秒加一点，超过 40 s 加得更多。
   - 标签由能量、低音、高频、歌词重复、主唱覆盖、鼓点驱动推断。
     - drop：响、鼓点驱动（冲击性鼓点 ≥1.5 个/秒，或半速的 ≥0.9 个/秒且低音满），主唱覆盖 < 0.35（只有切片也算）；紧跟 drop、同样响的有唱段落是 drop 的延续；drop 后面两小节以内的尾巴仍算 drop。
     - chorus：唱的是重复句；只在后面紧接着更响的**有唱**段落时才算预副歌——唱完直接进没人唱的 drop 的那段重复句就是副歌。紧挨副歌之前、差不多响、已经唱到副歌钩子句（全曲唱三次以上）的段也算副歌；但这段的句子大多只唱一次时不算——主歌可以用钩子句开头（接在 drop 的尾巴上，《溯》73.5 s）。
     - 12 小节以内反复唱的同一句（叠唱、口号）算一次（按小节不按秒：30 s 在 140 BPM 是 17 小节，在慢歌只有 8 小节），不当作会回来的钩子；第一个大段之后、一半以上的句子是这种只在一处喊三次以上的口号的段算 bridge（《Stronger》250 s）。
     - break：低音掉空或没人唱的短段夹在两个响段之间；6 小节以上、没人唱（或只零星唱一两句前面唱过的钩子，主唱覆盖 < 0.35）、低音比两侧大段低 10 dB 以上且明显更轻的也是 break（纯音乐和 EDM 的 breakdown，《溯》145 s）；breakdown 前鼓停、高频掉 6 dB 的两小节算它的开头。紧接着更响的大段的短段是 build；drop 前 4 小节以内、低音比 drop 低 8 dB 以上、能量低 15% 以上的段也是 build，上面唱着钩子句也一样（未来贝斯的铺垫：低音撤掉，军鼓滚奏、上升音效下唱副歌最后一句，《溯》42.6、111.2、155.8 s）。
     - bridge：两遍副歌/drop 之后、和各段主歌都不像的段；或唱的是前面没出现过的新词、且比之前每段主歌都响 10% 以上（抒情歌的高潮段）或句子少得多、拖得长。
     - intro / outro：第一句之前没唱的都算 intro；最后一个副歌/drop 之后明显变弱又没有主唱的都算 outro，从末尾往回，轻声重唱前面句子的段、没人唱的短尾巴也算 outro。
6. 鼓点：底鼓和军鼓的候选峰值各过一个小的逻辑回归判定（`hits.ts` 的 `KICK_GATE` / `SNARE_GATE`），特征是起音强度、盖过整体的程度、比之前 30–80 ms 抬高多少、150 ms 后的衰减、离拍子网格的距离。
   - 底鼓：主要看低频起音强度和是否在八分音符网格上（网格含正拍和反拍，节拍认偏半拍也不受影响）。按局部电平（±4 s 内每秒最大值的中位数，不低于全曲的一半）挑候选，安静副歌里的弱底鼓也能进候选。
   - 军鼓 / 拍手：主要看 1 kHz 以上的起音强度、衰减快、落在拍上（第 2、4 拍）。踩镲靠“不在拍上”分开，所以**军鼓依赖节拍相位正确**：节拍整体偏半拍时军鼓会大量漏掉。
   - 2026-10-01 以前的规则（低频要在 150 ms 内衰减到一半左右；军鼓 1–5 kHz 的上升至少是 5 kHz 以上的 2 倍）把底下有贝斯或带长尾的底鼓、流行歌里很亮的军鼓都当成了别的，反拍开镲反而当成了军鼓。用户：“鼓点识别有些不准啊”（《Save My Love》）。
   - 拟合（`tools/drums/`）：`separate.py` 用 htdemucs_ft 分出鼓轨 → `refonsets.py` 从鼓轨提参照起点（军鼓频段里前 40 ms 高频主导的算镲，干净鼓轨上这个比值明显分成两堆）→ `features.ts` 给插件的候选峰值算特征、标上是否对应参照 → `fit.py` 每首歌留出不参与拟合，比较留出歌上的 F。六首：Save My Love、This Feeling (Sped Up)、Clarity、Hurricane、TAKE MY LOVE、Stronger。
7. 示波器音乐（`xy.ts`，在 `prepare.ts` 里对另外解码的 44.1 kHz 立体声做，约 20 ms）：100 ms 窗口上左右差 ÷ 合的能量中位数 > 0.35，且 40 个 30 ms 窗口里左右轨迹在 2–25 ms 内最好的自相似残差中位数 < 0.2。缓存里七首普通歌的左右差 ÷ 合是 0.03–0.28（第一关就不过），Oscillofun 0.61、残差 0.06–0.08。
8. `bpmHint`：本机估计和提示值的某个倍频（×½、×2 等）相差 9% 以内时用来选倍频；和某个倍频的 3∶2 或 2∶3 相差 9% 以内、且速度图对提示值的支持不弱于本机估计时，也改用提示值那一档。对不上就忽略。

## 已知弱点

- 不给 `bpmHint` 时，慢抒情歌可能取到两倍速（《一程山路》138）。
- 恒速锁定按多数节拍定相位；整首大部分被带到反拍、或真有插入的半小节时会被抹平。半拍判定是经验规则，反拍上同时有底鼓和低音变化的歌可能被误移。鼓打贝斯按半速（87 BPM）跟，拍落在拍手上；它的底鼓频段被贝斯盖住，相位只能看拍手。《溯》给歌词时第一段主歌的重拍比后面晚一拍（20.8 s 处留下一个 3 拍的小节），不给歌词时是一条连续网格，哪个对没核实（段落边界只差一拍）。
- 速度曲线（`tempo.ts`）本身在切分很多的 drop 里仍会漂，现在靠锁定层兜住。
- 段落：只有歌词在变、音乐几乎不变的换段要靠歌词线索，短的预副歌（《Until I Found You》3 小节）切不出；一小节的铺垫不单独成段；副歌最后一个长音后接的旋律贝斯段（《Falling Again》80 s、155 s）没有可用的变化。
- 标签规则是按这 12 首调的经验规则；没有歌词时，低音掉空的主歌会被标成 break（《her》没有歌词文件），满鼓组加低音的主歌会被标成 drop（《溯》不给歌词时 20–34 s、75–103 s；它的边界也大多早一小节，把 drop 前低音先进来的那一小节算进 drop：±0.5 s 2/15、±1 小节 13/15，名称 8/16）。没有歌词时能量阈值都相对全曲：最响的不驱动段就算 chorus；新颖度 z 化后配固定的分段代价，从头到尾没有变化的歌也会被切段（手头没有这类歌可验证，没改）。
- 鼓点判定是在 6 首（多为电子流行，一首说唱）上拟合的；说唱里 808 贝斯音符仍常被当成底鼓（《Stronger》底鼓精确率 0.58），慢的摇摆抒情里军鼓会误报在底鼓上；鼓打贝斯的底鼓频段被 reese 贝斯盖住，检测不可靠。军鼓依赖节拍相位。没有歌词时 `vocal` 一律为 false。
- 逐字时间（2026-10-01 在插件里试过，没有上线；同日做成可选的对齐包，见 ALIGNER.md）：网易云只给逐行歌词时，每个字的时刻是按音节在句内平均分的估算。试过从音频里认：人声频段（250–3500 Hz）中值滤波后的上升减去鼓点作为起音曲线，每句用动态规划给每个词挑起点（间隔按音节、试多种语速、靠近行时间戳）。拿缓存里 16 首同时有逐字（yrc）和逐行（lrc）歌词的歌评测（逐行版去对齐，逐字版当答案，3420 个词，不算每句第一个词）：
  - 原来的平均分配：误差中位数 0.243 s，≤0.1 s 24%，≤0.25 s 51%。
  - 从音频认：调了几组参数都更差，0.27–0.29 s，≤0.25 s 46–49%。
  - 原因：起音曲线在真实字起点和别处的区分度只有 AUC 0.58–0.61（全频段起音 0.635，因为字常落在鼓点上）；就算知道每句真实唱多长再平均分也只到 0.218 s（误差主要是句内节奏不均）；逐行时间戳离真实第一个字本身就差 0.154 s（中位数）；真实字起点离十六分网格的距离（中位数 39 ms）并不比随机近，吸附到拍子上也更差。
  - 要明显变好得靠人声分离或语音模型做强制对齐，模型几十 MB 起、网易云的 Chrome 91 没有 WebGPU 也不让开 Worker，只能在主线程算，一首歌要几十秒以上，所以插件本体里没做；后来做成了插件外的可选对齐包（语音模型强制对齐，58 首上 ≤0.25 s 从 48% 到 82%），见 ALIGNER.md。

## 评测

```
bun tools/eval-analysis.ts [--song id,…] [--no-hint] [--no-lyrics] [--quick | --no-timing] [--bars] [--debug-sections]
```

歌单在 `tools/eval-analysis.ts` 的 `SONGS`：clarity、clarity-ncm、ticking、maybe、falling、shanlu、uify、stronger、hurricane、takemylove、combine、timeflies、su（有标注），spacewalk、limit、her（无标注）。`--no-timing` 每首只跑一次、不计时，调参时用；`--no-lyrics` 不给歌词（看插件拿不到歌词时的结果）。

`--bars` 打印每小节的响度、低音、高频电平和从这一小节开始的歌词行（`L序号:G重复组×出现次数`，b 为和声），以及每行的演唱起止时间和所在小节——只有编号和时间，不输出歌词文字，用来标注。`--debug-sections` 打印每个小节边界的得分（音频各项、歌词线索）和每段的标签依据（能量、主唱覆盖、重复度、鼓点、低音）。标准答案里 `"drop|chorus"` 表示两种都算对；汇总行给出全部有标注歌的合计（本地 Clarity 与网易云版重复，不计）：边界召回（标注边界 ±0.5 s / ±1 小节内有估计边界）、边界精确率（估计边界 ±0.5 s / ±1 小节内有标注边界，切多了会降）和名称。

本地歌原地读取、ffmpeg 解码到临时目录后删除（`EVAL_PCM_CACHE=<目录>` 可保留缓存）；网易云缓存里的歌从开发服务器 `http://localhost:5190/ncm/audio/<id>` 取，需要先 `bun run dev`。网易云会限流：歌词没取到时缓存里记下，下次再取；已知的百科 BPM 写在 `SONGS` 里，不再请求。
