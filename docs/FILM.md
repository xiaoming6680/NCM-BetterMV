## 取舍

- **歌要有张力**：这是用户对第一版的意见。六首歌都只取 drop 或副歌最响的一两小节：游戏主题曲的金属核 drop、国风电子、国风史诗、说唱、两首电子舞曲。第一版的抒情歌整首拿掉。
- **口号落在第一个 drop 上**：口号用用户的原话，“每只歌”改为“每一首歌”，分两行，不加标点；第二行的“MV”用标志的红色渐变，字从模糊中浮现（上一版用户认可的发布会式大字）。字压在浑天仪上：浑天仪本来就是插件在 drop 前做的蓄力，字在蓄力时出现；drop 落下时字退去、画面对焦，口号和第一下冲击同时落地。开头三秒就有画面，不用黑底。
- **首尾是同一首歌**：开头用它的第一个 drop，结尾用它的最后一个 drop，片子有完整的起落。第二次的推进隧道换了机位（roll），之后接光球。
- **每首歌一个不同的场景**：浑天仪、推进隧道、频谱隧道、宣纸水墨、字墙、谢尔宾斯基分形、万花筒、光球，网格里还有门格海绵。分形是 0.9.0 新加的，片子里放了两种。
- **换歌用插件自己的等待页**：封面和歌名就是字幕，不另加说明文字；等待页只占下一首歌进来前的一拍，声音在小节线上切换，下面垫一声反向镲片。封面放大成画面，MV 的颜色本来就取自封面，正好接上。
- **结尾的网格**：六首歌同时播放，直接呈现“每首歌都有自己的 MV”，不用再写一遍口号。其他五格重放各自那一段；比网格短的段落放慢一点，让每格停在观众刚看过的那个场景上。
- **只宣传**：片尾是标志、名字、“网易云音乐插件”，下面一行小字仓库地址（用户后来要的：“宣传片最好提到一嘴仓库”）；不写下载方式和“开发中”。网格退去后只留黑底和名字，不再把最后一首的画面铺回整屏。
- **只出横屏**：用户的要求。渲染脚本里的竖屏选项已删掉。
- **克制**：片子本身不加闪白和辉光；所有位移从静止起步、平稳停下；换歌时上一首退后、变柔，不硬切。
- **声音**：每段按响度对齐到 -13 LUFS（最后一段 -12.5），整条再做响度标准化（成片 -13.8 LUFS，真峰值 -1.8 dBFS）。
- **封面**：取 0:31.5 的谢尔宾斯基分形，左边压口号，左下角是标志。推进隧道和光球的画面里有这首歌的歌词，会和口号抢；万花筒中间有一道镜像接缝，定格后像画面出错。

取舍：

- **选曲**：中间每首都是能量最高的那几小节，没有安静的前奏和慢歌；同一路的旋律电子，从 Clarity 起，接起来不跳戏。颜色：金、紫橙、橙红、紫灰、绿、紫蓝。第一稿里讲“四种风格”用到的说唱、墨、抒情歌这一版不放了，四种风格只在结尾的数字里提一句。
- **讲解只讲插件独有的**：读懂整首歌（用户之前点过的亮点“智能识别歌曲结构”）、每首歌一架浑天仪（另一个亮点）、颜色只取自封面、歌词长在画面里、四种画风、每次播放重新编排，最后是数量。每处一句标题加一行说明，放在左下角、底下压一层渐暗，样式和片头口号一致（PingFang，从模糊中浮现）；画面和音乐一直在走，不做“标题→演示”的幻灯片（用户否过）。
- **画风只在一处出现**：插件平时会随机给部分段落套画风，片子里关掉（播放器的 `forceLook` 'none'），只在“四种画风”那两小节逐个展示。
- **每次播放都重新编排**：同一首歌的同一小节，用另外两个种子各播一次，三格并排；另两格的场景就是那两个种子在这一小节本来排到的。两格按格子大小画（见下面“显存”）。
- **网格**：六首歌各一格（3×2），每格重放这首歌最长的那一段；除了最后一首（从全屏缩进格子里），其余按格子大小画。
- **显存**：一个播放器按整屏画过一次后，后期缓冲要占将近 1 GB。第二稿第一次渲染时八个播放器都按整屏常驻，到第四、五首歌开画时显存分配失败（`GL_OUT_OF_MEMORY`），八个 WebGL 上下文一起丢失，后半部片子全白，渲染却照常结束。现在不在画面上的播放器缩到 64×36（`film/shared.ts` 的 `fit()`），缩完 `flush()` 一次，旧缓冲才真正释放（不 flush 的话，要等它下次再画才还）；整片显存从一路涨到 9.3 GB（整机）变成稳定在 6.5 GB 左右。第二个坑是系统内存：GPU 进程的分配同样记在系统的可提交内存上，而这台机器同时开着几十个会话，可提交内存只剩几 GB；每个播放器又按整首歌的方案把所有场景都建出来，八个播放器加载完 GPU 进程就占 4.3 GB，渲染到 52 秒又一次分配失败（ffmpeg 也报内存不够）。现在播放器只建片子里看得到的场景（`retake` 里把片子不播的镜头改成播的那几个场景），加载后 GPU 进程降到 1.6 GB。
- **刻进去的镜头归哪一段**：按镜头中点算。按起点算时，刻在 drop 重拍上的镜头会落进前一段（差几毫秒），导演层把整个镜头当成“drop 前半拍”黑掉。
- **字体**：标志旁的“BetterMV”用插件界面的标题字体 Segoe UI Variable Display（用户说 Archivo Expanded“好丑，以后都不要用”，两版片子和封面都改了）。

## 渲染

```sh
bunx vite --config vite.frozen.config.ts --port 5192                # 冻结的开发服务器（不重载，渲染中途改代码不受影响）
BMV_SERVER=http://localhost:5192 bun film/render.ts                 # 成片
BMV_SERVER=http://localhost:5192 bun film/render.ts --stills 2,30   # 静帧
BMV_SERVER=http://localhost:5192 bun film/render.ts --cover         # 封面（宣传版取成片里的帧；加 --reel 是效果版，当场渲染不带字幕的帧）
BMV_SERVER=http://localhost:5192 bun film/render.ts --reel          # 效果版（--stills 等选项同样可用）
```

歌曲来自网易云的本地缓存，不进仓库（`build/` 已忽略）。预览：开发服务器的 `/film/` 和 `/film/reel.html`（`?t=30` 从 30 秒开始）。两版共用的部分（载歌、等待页、关键词式的字、小节换算）在 `film/shared.ts`。

渲染时别同时跑别的浏览器渲染任务，默认只开一个页面：每个页面给六首歌各建一个 WebGL 渲染器，开两个页面并行时显存吃紧，个别场景会丢内容（声道只剩中间的圆环、万花筒黑 0.2 秒），换成一个页面渲染同样的帧就是完整的。另一次渲染时内存不够，编码器中途丢了 42 帧却照样正常退出，后半段画面比声音早 0.7 秒；现在渲染完会核对帧数，不对就报错；渲染中途哪个 WebGL 上下文丢了也立即报错，不再输出白帧。
